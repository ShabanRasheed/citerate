1 · QUERY GENERATOR
lib/query-generator.ts
Crawl + category blend, provenance kept

Onboarding now crawls the domain — homepage title, meta description, H1/H2s, sitemap slugs — and derives real queries from what the site says about itself (“best {category phrase}”, heading and slug phrases). The deterministic template becomes the floor, not the whole set. Search Console queries join as a third source after OAuth. Every row is labelled crawl, gsc, or category in the database.

failure mode → category-only within 5s; onboarding never blocks on a slow site
2 · PADDLE PRICE IDS
api/billing/checkout.ts · addon.ts · portal.ts
Config, not code

Price ids come from the Paddle dashboard, so hardcoding them was never right. They now live in one PADDLE_PRICE_IDS JSON var covering all four plans, both intervals, and the four add-ons. PADDLE_ENV=sandbox routes every call to Paddle's sandbox. Add-ons charge through hosted checkout when configured — the counter is raised by the HMAC-verified webhook on payment, never by a redirect.

failure mode → unchanged readable 501 with the exact var to set
3 · SEARCH CONSOLE OAUTH
api/connect/gsc/callback.ts · lib/seal.ts · 0003
Callback, sealed tokens, query blend

The consent hop now mints a single-use 160-bit state (KV, 10 minutes); the callback burns it, exchanges the code, and stores the refresh token in a new gsc_connections table — sealed with AES-GCM under SESSION_SECRET, so a leaked row is ciphertext and rotating the secret invalidates every token. It then pulls the domain's top 28-day GSC queries into the set, deduped, capped at the plan limit, labelled source: 'gsc'.

failure mode → denied/expired/error each land back with a plain-words note
4 · PDF RENDERER
api/reports/[id]/pdf.ts
Rendered once, stored forever

The first download renders /reports/<id> with Cloudflare's Browser Rendering binding — handing the renderer the caller's own cookies, so it sees exactly what the caller sees — writes the PDF to R2, and stamps artifact_key. Every later download streams the stored file. A snapshot's PDF is rendered once and never recomputed, the same promise the payload already makes.

failure mode → no BROWSER binding falls back to the print path, stated on the page
