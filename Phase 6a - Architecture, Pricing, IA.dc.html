Citerate · Phase 6a Decisions before pages

Website architecture, pricing, and site map

Eleven pages is a lot to design blind. This board settles the three things that shape every page: the stack the site is built on, the pricing the site has to sell, and what each URL is for. Two open choices sit at the bottom for you to pick before I design the home page.

01

How Bootstrap gets mapped
Bootstrap 5.3 comes in through npm as SCSS, not a CDN link, so nothing is overridden after the fact. In _bootstrap-map.scss your tokens become Bootstrap's variables before it compiles: $primary: #0E7C66, $danger: #C43D3D, the spacer map set to the 4px scale, radii to 6, 10, 14, and the font stacks to Source Serif, the system stack, and JetBrains Mono. Bootstrap then outputs your brand instead of its own.
Only the parts you use get imported: reboot, grid, forms, buttons, dropdown, modal, offcanvas, accordion, utilities. Carousel, toasts, tooltips, badges, and the rest stay out. That keeps the marketing CSS near 30 kB before compression.
Dark mode rides Bootstrap's own data-bs-theme attribute, so one toggle drives both your variables and theirs.
How the JavaScript splits
Marketing site runs your own ES modules and no Bootstrap JavaScript at all. Nav, theme, consent, pricing toggle, and the scan form are roughly forty lines each. GSAP with ScrollTrigger loads only on the pages that have a scroll narrative, and only above 900 pixels wide. Charts on marketing pages are hand built SVG so they cost nothing and print correctly.
Dashboard is the opposite balance, as you asked. Bootstrap's JavaScript handles modal, offcanvas, dropdown, and accordion. Alpine drives small stateful pieces like filter chips and row expansion. ECharts draws the trend and cause charts. Custom code stays limited to what the product actually invents.
Icons ship as one Lucide SVG sprite built at deploy time. No icon font, no layout shift, no network request per glyph.

What a tracked query means
One prompt, checked on every engine in your plan, on every refresh in your plan. Engines and refresh frequency are not separate meters. Buyers in this category are used to being nickel counted on both, and not doing it is a reason to choose you.
Going over does not stop the scan. It shows a banner and bills the overage block at the end of the cycle.
Add ons
100 extra queries $19. Extra domain $39. On demand rescan pack of 10 for $15. Historical backfill of 90 days $99 once. Additional seat $12 on Growth, included on Scale up to the seat count.
No add on unlocks a gated feature. Add ons only buy volume, which keeps the tier story honest.
Why these numbers
Tools in this category cluster at roughly $100 entry and $400 to $500 for the plan that names competitors. Starter sits deliberately below that cluster so a solo marketer can expense it without approval. Growth sits mid cluster with the one feature people actually upgrade for. Scale is where reporting and white label live, because that is bought by someone with a budget line.
Gross margin holds because engine calls are the only variable cost and rollups cap storage growth.

Two choices for you

reply with the ids, for example 1b and 2c
Set 1 · how the method gets explained
1aFour stage pipeline
1Build the prompt set
2Ask every engine
3Match citations
4Attribute the cause
Vertical scroll, one stage pinned at a time, the diagram advancing as you go. Familiar, easy to scan, and the safest to build. Risk is that it reads like every other process section on the internet.
1bOne query, followed
"best crm for startups"
ChatGPT cites 3 sources. None are yours.
answer text with two citations highlighted
Cause: AIO displacement
The whole page follows a single real query from prompt to verdict, the way a lab explains a test. Every abstraction gets a concrete example attached to it. Best fit for the measurement pitch and for your type voice. Most work to build.
1cSplit screen, sticky
Prompt set Engines Matching Attribution
live panel
Text scrolls on the left, one sticky panel on the right swaps its diagram in place. Dense, technical, and it doubles as the docs overview. Weakest on mobile, where it collapses to stacked cards.
Set 2 · home page rhythm across ten sections
2aInstrument first
Dark hero with the scan field, then the live readout immediately, then method, then proof, then pricing preview. The number arrives before any argument. Fits the measurement framing and the free scan CTA better than anything else.
2bProblem escalation
Three sections building the loss before the product appears at the midpoint, dark and loud. Converts hard on cold traffic. It also makes the page feel like an ad, and it argues rather than measures.
2cReport, read top to bottom
The page is laid out like one of your own reports: numbered sections, figure captions, a methodology note at the end. Unmistakably yours and it makes the product feel serious. Slowest read, and it needs strong copy to carry it.
Flags before we build
The free scan costs you real engine calls per submission with no email captured. Turnstile plus one scan per domain per day plus a KV cache is the plan, and the caching is what keeps it affordable. Worth agreeing on before the page ships.
Pinned scroll narrative and Lighthouse 95 pull against each other. GSAP loads on two pages only, above 900 pixels only, and the pinned sections degrade to plain stacked sections when reduced motion is on. Mobile gets no pinning at all.
Ten pages with no logos, no quotes, and no case numbers is the real constraint. The pages that lean on proof will carry marked placeholders, and two of them stay unpublished until you have one customer willing to be named.
Docs and API reference describe an API that does not exist yet. Suggest designing the page and shipping it behind a coming soon state rather than writing endpoints we will change.
