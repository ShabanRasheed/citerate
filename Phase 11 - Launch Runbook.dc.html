THE EIGHT STEPS · IN ORDER · EACH ONE VERIFIABLE
01 · BINDING IDS
you · 5 min
One database, two front ends

Paste the same D1, KV and R2 ids the marketing repo already uses into wrangler.toml. Different ids mean two databases and a dashboard that can't see what the scanner wrote.

wrangler pages project create citerate-app
verify → pnpm preflight shows no REPLACE_WITH_
02 · PADDLE
you · 30 min
Twelve prices, created once

Four plans × monthly/yearly, plus the four add-ons. Paste the map into PADDLE_PRICE_IDS and flip PADDLE_ENV to production. Test in sandbox first with the same shape.

{"starter":{"month":"pri_…","year":"pri_…"},…,"addons":{"extra_queries":"pri_…",…}}
verify → preflight: 8 plan prices + 4 add-ons, all pri_…
03 · GOOGLE OAUTH
you · 15 min
One client, two uses

The same client serves sign-in and Search Console. Register the redirect uri verbatim — a trailing slash is a mismatch. Add the Search Console read-only scope.

https://app.citerate.com/api/connect/gsc/callback
verify → connect once; gsc_connections gains a sealed row
04 · SECRETS
you · 5 min
Five, none in the repo

SESSION_SECRET is the load-bearing one: it seals GSC refresh tokens as well as sessions, so rotating it signs everyone out and invalidates stored tokens. 32+ random bytes, generated not typed.

wrangler pages secret put SESSION_SECRET --project-name=citerate-app
verify → wrangler pages secret list shows five names
05 · INSTALL & TYPECHECK
you · 3 min
The puppeteer dependency

Phase 10 added @cloudflare/puppeteer for the PDF route. Install, then typecheck before you spend a deploy on a compile error.

pnpm install && pnpm check
verify → astro check and tsc both clean
06 · MIGRATIONS
you · 2 min
0003 before the deploy, not after

Deploying first means the connect route writes to a table that doesn't exist. Run remote migrations, confirm gsc_connections landed, then ship.

pnpm db:migrate:remote
verify → d1 execute "select name from sqlite_master" lists it
07 · MOCKS OFF
you + scanner · gated
The one that decides whether launch is real

Every readout still comes from mocks. Flip USE_ENGINE_MOCKS to false only once the scanner Worker answers in production — with mocks on, the app is a convincing demo, and the method promises on the marketing site would be false.

USE_ENGINE_MOCKS = "false"  # blocks a production deploy until set
verify → run one real scan; the surface|proxy label matches the source

you · 4 min
Gated, then smoke-tested

Preflight runs, build runs, Pages takes it. Then walk the eight smoke checks below on the live domain before you tell anyone the door is open.

pnpm deploy
verify → the smoke list, all eight

any failure → rollback, don't patch forward

GO / NO-GO — THE TWO OPEN ITEMS, AND MY CALL
GO
2FA enrolment — ship without it. Auth is passwordless already: there is no password to steal, and the session is short-lived for untrusted devices. Enrolment screens buy little at launch and cost a full flow with recovery codes. Revisit when the first agency account asks, which is the honest trigger.
GO, FIX FAST
Fonts — ship, then copy the four woff2 within the week. Without them the display serif falls back to Georgia: readable, but the verdict sentence loses the voice the brand is built on. It's a file copy, not a decision — the only reason it isn't done is that nobody owned it.
NO-GO
Mocks on is not a launch. Step 07 is the real gate. Everything else here is plumbing; that one is the difference between a product and a demo, so preflight blocks on it rather than trusting anyone to remember.
IF IT GOES WRONG

Pages keeps every deployment. Roll back to the last good one rather than patching forward under pressure — the database is shared, so a bad app deploy never corrupts the marketing side.

wrangler pages deployment list --project-name=citerate-app
wrangler pages deployment tail

A migration is the exception: 0003 only adds a table, so a rollback of the app is safe with 0003 applied. Never roll a migration back to fix a deploy.
