Switching the engines from mock to real

One flag decides it. With USE_ENGINE_MOCKS=true the pipeline runs completely but the answers are deterministic fakes. Set it to false and the same code asks the real engines. Nothing else changes — same queries, same citation maths, same screens.

A missing key does not break a scan. That engine is marked unavailable for the run and the rest proceed, so you can start with one key and add the others later.

Copilot and Claude are listed on the Scale tier and currently route through keys you already have rather than their own. If you sell that tier, they need real clients first — worth knowing before the pricing page goes live.

Turning it on locally

Open citerate\.env, paste the keys, and flip the flag:

OPENAI_API_KEY=sk-...
SERP_API_KEY=...
USE_ENGINE_MOCKS=false

Then also set USE_ENGINE_MOCKS = "false" in citerate\workers\scanner\wrangler.toml, because the scanner reads its own vars, not your .env. Missing that is the usual reason someone pastes keys and still gets mock answers.

pnpm preflight:local
expect
USE_ENGINE_MOCKS false — scans hit the real engines. If a key is unset while the flag is false, preflight blocks and names it. Restart both terminals afterwards; neither picks up config changes while running.

Turning it on in production

The engine keys belong to the scanner Worker, not the Pages project. Set them there, then redeploy the scanner.

cd C:\citerate\citerate
npx wrangler secret put OPENAI_API_KEY     --config workers/scanner/wrangler.toml
npx wrangler secret put SERP_API_KEY       --config workers/scanner/wrangler.toml
pnpm scanner:deploy
pnpm scanner:tail

The production preflight treats a true flag as a hard block, not a warning — you cannot accidentally ship a live site that serves fake numbers.

What a scan costs

Priced by multiplication, not by scan. A free scan is capped at 25 queries, and each query is asked 3 times per engine — repetition is the whole method, since these engines answer differently run to run. Two engines makes 150 calls per scan.

knobdefaulteffect
FREE_SCAN_QUERY_LIMIT25Drop to 5 while testing. Linear on cost.
RUNS_PER_ENGINE3Set to 1 while testing. Also linear. Below 3 the citation rate gets noisy.
FREE_SCAN_ENGINES2chatgpt and google_aio. Cut to one to halve the spend.
FREE_SCAN_CACHE_TTL_SECONDS86400One live scan per domain per day. Refreshing the page does not re-spend.

I will not quote you per-call prices, because they change and I would rather you read them off the provider's page than trust a number from me. Model pricing is per token at platform.openai.com/pricing; SERP providers charge per search on a monthly plan. Set a hard spend cap on the OpenAI account before your first real scan — that is the one safeguard the code cannot give you.

For your very first real run I would set the limit to 5 queries and runs to 1. Ten calls, cents of spend, and you learn whether the plumbing works before you learn what it costs.

Your first real scan

Enter shabanrasheed.com without the protocol — the form normalises it, but bare hostnames are what the cache keys on. Watch the scanner terminal while it runs: you will see one log line per engine call, and any key problem shows up there as unavailable with a reason attached.

What to expect from it

A personal portfolio site will almost certainly come back with a citation rate near zero, and that is the correct answer rather than a bug. These engines cite sites they consider authoritative on a query, and the generated queries for a single-person portfolio have very few natural citation opportunities. Do not read a low number as the scanner failing.

If you want a first scan that produces an interesting-looking result — several cited queries, competitors with real share, a fix queue with something in it — pick a domain that already ranks for commercial queries. Somewhere you have worked, a client, or a competitor in a category you know. The product tells a much clearer story on a site that has something to lose.

One more honest note: the queries are generated from the domain, so their quality decides whether the scan means anything. Read the query list on the first real run before you judge the numbers underneath it.
