Phase 13 · responsive · 2026-08-03

Every breakpoint in one file, every screen at every size

Two jobs. First, the CSS was reorganised: no partial contains a width media query any more — they all sit in one _responsive.scss per repo, in descending order, with a new 375px step for small phones. Second, this board is the proof: all 38 routes with their layout state at four widths, the six end-to-end flows, and thirteen screens drawn at actual 375px.

AFTER · ONE FILE PER REPO

Partials are desktop-first and query-free. The responsive file is imported second-to-last; only print follows it, so paper still wins over screen.

// main.scss tail, both repos
@use "06-utilities/utils";
@use "07-responsive/responsive";
@use "06-utilities/print";

Inside that file: width queries in descending order under banner headings, then a single prefers-reduced-motion block at the very bottom. Adding a breakpoint means inserting it in sequence, never appending.

04

Six flows, walked at 375px

Free scan → claim
home → form → progress → /scan/[token] → claim

Field and button stack at 599. Progress readout keeps its 150px rail. Result table scrolls sideways; the claim CTA is a full-width 48px target.

Sign-up → onboarding → overview
/sign-up → /check-email → domain → connect → queries → /overview

The one real bug this pass found: six fixed 48px OTP boxes overflowed every phone. They now share the row fluidly at 599 and shrink to 44px at 375.

Gap → fix → verify
/queries → row detail → /fixes → owner → rescan → proof

Row detail opens in place as a card. Fix actions go full-width and split the row evenly at 375; the before → after proof block wraps rather than clipping.

Invite a teammate
/settings/team → invite → /invite/[token] → role

Team list is a data table, so it becomes cards at 639 with role and last-seen as labelled rows. Accept screen is the same 440px auth card.

Upgrade
locked region → /settings/billing → Paddle → return

Locked veils keep their badge and one-line reason at 375 — the blur never hides the sentence explaining the gate. Paddle's own overlay is responsive.

White-label report
/settings/brand → /reports → /reports/[id] → PDF

Report reading is fine on a phone; PDF output is unaffected — print CSS loads after the responsive file, so paper geometry ignores every breakpoint.
