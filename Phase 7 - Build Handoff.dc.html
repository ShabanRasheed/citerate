Citerate · Phase 7 Build handoff · ready to deploy

The site is code now, not a board

Just over a hundred files in /citerate: Astro 5 on Cloudflare Pages, the full D1 schema, the scan-queue Worker, the token system compiled through Bootstrap, every page from phases 6b–6d, and the API routes behind them. It runs locally in five minutes with no Cloudflare account and no engine spend — engine clients ship with deterministic mocks. Download it below.

Run it now
pnpm install
cp .env.example .env
pnpm db:migrate:local
pnpm db:seed:local
pnpm dev            → localhost:4321
pnpm scanner:dev    → drains the scan queue
The scan form works end to end against mock answers. Zero API cost, deterministic results.
Ship it
wrangler d1 create citerate-db
wrangler kv namespace create SCAN_CACHE
wrangler kv namespace create RATE_LIMIT
wrangler r2 bucket create citerate-artifacts
# paste ids into both wrangler.toml files
pnpm db:migrate:remote && pnpm deploy
pnpm scanner:deploy
Secrets go through wrangler pages secret put — never a file. Full list in the README.

03

The scan queue, without a queue service

How a scan runs
1. POST /api/scan normalises the domain, checks the KV cache, clears Turnstile and both rate limits, then writes a domain, a 25-prompt set, a scan row, and one scan_jobs row per query per engine.
2. The cron Worker ticks every minute, claims a batch of twelve, resets stale claims older than five minutes, and asks each engine three times.
3. Raw answer text goes to R2 — that is what "show me the receipt" reads. Observations, citations, and discovered competitors go to D1.
4. When every job settles, the scan closes with a rate, a confidence band, and a cause mix written to daily_rollups. Charts only ever read rollups.
Cost and failure behaviour
A tick is one Worker invocation. At 100k invocations a day free, the cron alone is ~43k a month — the queue is genuinely free until scan volume, not tick count, forces Cloudflare Queues.
A failing engine marks that job error after three attempts and the scan closes as partial, not failed — a missing engine is a coverage note, not a broken product.
A missing API key marks that engine unavailable for the run instead of throwing, so you can ship with two engines and add the rest later.
USE_ENGINE_MOCKS=true gives deterministic answers per query and engine, so the whole pipeline is developable and testable at zero spend.
