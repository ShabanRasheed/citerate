Getting Citerate onto GitHub and Cloudflare

You said one repo — github.com/ShabanRasheed/citerate — holding both folders. That works, and it is the simpler choice. It does mean the repo root contains two projects rather than one, and Cloudflare needs to be told which folder each deploy builds from.

Three things get deployed: the marketing site as a Pages project, the dashboard as a second Pages project, and the scanner as a Worker. They all point at one D1 database, which is why the database gets created before any of them.

A · Push to GitHub

Create the repo empty on GitHub — no README, no gitignore, since both folders already have their own. Then from the folder that holds them both:

cd C:\citerate
git init
git add .
git commit -m "Citerate: site, dashboard, scanner"
git branch -M main
git remote add origin https://github.com/ShabanRasheed/citerate.git
git push -u origin main
Before that first push, confirm git status does not list any .env file or the .wrangler folder. Both repos gitignore them, but check anyway — a leaked key in git history is a bad afternoon. Add a root .gitignore with .env and .wrangler/ if you want belt and braces.

B · Cloudflare account

Sign up at dash.cloudflare.com. The free plan covers Pages, Workers, D1, KV and R2 at the volumes this project starts at. Then log the CLI in — it opens a browser and grants your machine access.

cd C:\citerate\citerate
npx wrangler login
npx wrangler whoami
expect
Your email and an account id. Copy that account id somewhere — you will want it if a later command asks which account to use.

C · Create the resources

Four commands, run once ever. Each prints an id or a confirmation. Keep the output — the next stage pastes those ids into config.

npx wrangler d1 create citerate-db
npx wrangler kv namespace create SCAN_CACHE
npx wrangler kv namespace create RATE_LIMIT
npx wrangler r2 bucket create citerate-artifacts

There is no queue to create. The scan queue is a table in D1 plus a cron trigger on the scanner, which is why this runs at zero cost until real volume forces the change.

Then build the tables in the real database:

pnpm db:migrate:remote
note
Do not seed production. The seed is demo data.

D · Paste the ids into three files

Every REPLACE_WITH_ placeholder has to become a real id. There are three files and they must agree, because all three deploys bind to the same database.

filewhat to replace
citerate/wrangler.tomldatabase_id, both KV ids
citerate/workers/scanner/wrangler.tomlthe same three ids
citerate-app/wrangler.tomlthe same database_id

While you are in those files, change the [vars] block in citerate/wrangler.toml: PUBLIC_SITE_URL and PUBLIC_APP_URL currently say citerate.com. Point them at whatever domain you are actually using, or at the pages.dev URLs for now. Getting these wrong means the site links people to a domain that does not exist.

E · Set the secrets

Secrets never go in a file. Each command prompts you to paste the value. The Pages project needs five; the scanner needs the engine keys, which Phase 22 covers.

npx wrangler pages secret put SESSION_SECRET        --project-name=citerate
npx wrangler pages secret put TURNSTILE_SECRET_KEY  --project-name=citerate
npx wrangler pages secret put RESEND_API_KEY        --project-name=citerate
npx wrangler pages secret put PADDLE_API_KEY        --project-name=citerate
npx wrangler pages secret put PADDLE_WEBHOOK_SECRET --project-name=citerate

Three of those need accounts of their own first: Turnstile is free inside Cloudflare, Resend sends the verification and report emails, Paddle handles billing. Until Paddle is live you can set placeholder values — nothing except the checkout route reads them.

The dashboard needs its own copy of SESSION_SECRET, and it must be the identical value, or a session made by one half is unreadable by the other:

cd C:\citerate\citerate-app
npx wrangler pages secret put SESSION_SECRET --project-name=citerate-app

F · Three deploys, in this order

Each deploy runs the preflight first and refuses to continue if something is missing. That refusal is the feature — read what it says rather than reaching for deploy:force.

commandresult
1cd citerate && pnpm deployMarketing site live at citerate.pages.dev.
2pnpm scanner:deployScanner Worker live, cron ticking. Watch it with pnpm scanner:tail.
3cd ..\citerate-app && pnpm deployDashboard live at citerate-app.pages.dev.

Then run a real scan on the live site and confirm it finishes. If it queues forever, the scanner is not seeing the same database — the ids in step D disagree.

G · Domains

The design assumes two hostnames: the site on the root domain, the dashboard on app.. In the Cloudflare dashboard, add a custom domain to each Pages project, then update PUBLIC_SITE_URL and PUBLIC_APP_URL and redeploy both. Cookies are scoped so a session on the root domain is valid on the subdomain, which only holds if they share a registrable domain — so app.yoursite.com, not a separate domain.

Automatic deploys on push

You asked for code on Git and deploys on Cloudflare, and this is the piece that joins them — Cloudflare watches the repo and builds every push, so you stop running deploy commands.

Do it second, not first. It has been parked on purpose: connecting Git means Cloudflare's builders run the build instead of your machine, and each Pages project needs its root directory set to the right subfolder — citerate for one, citerate-app for the other — with the build command and output directory to match. The preflight gate does not run there, so a misconfigured value ships silently instead of being blocked.

Get one manual deploy working end to end first. Then say the word and I will write the exact settings for both projects, plus what to do about the scanner, which Git integration does not cover.
